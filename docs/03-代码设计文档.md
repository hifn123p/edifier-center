# 03 · 代码设计文档（Edifier Center）

> 本文是实现的权威蓝图，v1.1 与仓库代码同步：本地仅静态编写（**无 .NET SDK**），编译 / 测试 / 打包 / 发布全部由 **GitHub Actions** 在 windows-latest 上完成；产物为**单文件 exe**；运行期数据（config / logs / diagnostics）落在 **exe 运行目录**（可移植式布局）。协议依据 [02-协议参考-MR5BT.md](02-协议参考-MR5BT.md)，UI 依据 [ui.html](ui.html)。

## 1. 目标与约束

- 托盘常驻、轻量（空闲内存目标 ≤60MB）、符合 Windows 11 Fluent 规范；
- **本地零构建依赖**：仓库在 CI 上验证（`.github/workflows/ci.yml`），每次 push 全量编译 + 单测；
- 单实例、无后台服务、无管理员权限、无通知打扰；
- 音频链路（4i4 → XLR）零侵入，BLE 仅控制通道；
- 协议层纯逻辑、可单测；BLE 层经接口隔离（可 mock）；
- 安全红线固化在代码结构中（`CommandId` 白名单枚举——`0x07/0xCE/0xCD/0x45/0x46` 与 OTA 类不存在代码路径）。

**NuGet 依赖**：仅 tests 有 `Microsoft.NET.Test.Sdk` / `xunit` / `xunit.runner.visualstudio`（`*` 通配到最新稳定）。src 三项目零第三方包。

## 3. 分层与数据流

```
UI (WPF, UI 线程)
 │ 绑定只读 SpeakerState（MainViewModel，Raise 粗粒度刷新）
 │ 命令：VM 节流(150ms) → Enqueue
 ▼
Ble 层：EdifierSession
   ├─ 写队列 Channel<byte[]>(32, DropOldest) → WriterLoop → WinRtTransport.WriteAsync(WriteWithResponse)
   ├─ Notified → FrameCodec.TryParse → ResponseParser → StateStore.Apply（乐观更新 + 推送校正）
   ├─ 轮询保活 ≥5s（66/D5/68/61）+ 首读仪式（D8→66/D5/43/C6/F2）
   └─ 断线：ConnectionStatusChanged / 写失败 / Disconnected → 退避(1/2/5/10/30s) 重连
```

原则：**UI 永不直接触碰 GATT**；协议层不知道 BLE；BLE 层不知道 WPF。

## 4. 会话状态机（EdifierSession）

```
Idle ─Start─► Scanning ─命中服务UUID─► Connecting ─订阅CCCD+首读─► Ready
   ▲              │超时/未发现                │ 失败：服务未暴露→提示按配对键    │
   └─ StopAsync   └────── 退避 1/2/5/10/30s ◄─┘                                │
                  Ready ──ConnectionStatusChanged/写失败/ForceRestart──► Reconnecting（回退避）
   ForceRestart（睡眠唤醒/用户点击）在任意等待点打断 → 立即重扫，退避清零
```

- 扫描：`BluetoothLEAdvertisementWatcher(Active)`，广播 ServiceUuids ∈ {3a01, 7e03}；
- Ready 期子任务（写循环/轮询）挂在 linked CTS 上：断线/重连即终止，避免跨会话双消费；
- 诊断：断线时把最近 200 帧（hex）+ 状态快照写入 `运行目录\diagnostics\last-session.json`。

## 5. 关键流程

**音量（滑条拖动）**：Slider.ValueChanged → `VM.SetVolumeFromUi` → 乐观 `Apply`（UI 立即反馈）→ 150ms 合并 → `0x67` → 音箱推送 `0x66` → 状态校正。物理旋钮改动仅走推送路径——UI 实时跟随（omarchy 已验证）。
**静音**：无已验证 mute opcode，M1 用音量法（记 `_lastNonZeroVolume`，静音=写 0，取消=写回）。
**EQ 单段**：滑条 `UpdateSourceTrigger=PropertyChanged` → `BandVm.GainDb` → 200ms 合并 → diff 出变化波段 → `0x44 [byte0][index][freqHi][freqLo][gain]`（byte0 取查询响应原样回写）。
**声学调校**：低切/斜率/空间/桌面任一变更 → 250ms 合并 → `0xC4 [mode][index][byte0][lowCut][slope][space][desktop]`；恢复默认 = byte0 置 1 一次。
**模式切换**：`0xC4 [mode]` 单字节。

## 6. 线程与并发

- **UI 线程**：绑定 + 命令节流（DispatcherTimer）；`StateStore.StateChanged` 经 `Dispatcher.BeginInvoke` 封送；
- **会话任务**：RunAsync 主循环（扫描/连接/退避）+ Ready 期子任务（WriterLoop / PollLoop，挂在 linked CTS）；
- **状态交换**：不可变 record + `Volatile.Read/Write`，无锁；通知回调不做任何 UI 操作；
- **停机**：CTS 贯穿 → StopAsync await 主循环 → transport.DisposeAsync（5s 强退兜底在 App）。

## 7. 错误处理

| 情形 | 处理 |
|---|---|
| GATT 服务未暴露 | 抛 IOException（消息含"按配对键"引导）→ 退避重连；连续失败时用户侧表现为托盘灰态 |
| `Unreachable` / 缓存怪癖 | Uncached 访问 + 退避重连 |
| 校验和失败帧 | 丢弃 + 日志计数，不重置连接 |
| 未知 opcode（CC/DD/其他） | 记 hex 日志，不猜测语义 |
| 写失败 | WriterLoop 抛出 → 会话中断流程 → 退避重连（无重试轰炸） |
| 全局异常 | `DispatcherUnhandledException` 兜底 → 日志 + 不崩溃 |

## 8. 运行期数据布局（可移植，全在运行目录）

```
<exe 所在目录>/
├─ EdifierCenter.exe
├─ config.json                 # 设置 + 校准结果（calibration 区块）
├─ logs/
│  └─ edifier-20261101.log     # INFO/DEBUG/ERROR，按天分文件
└─ diagnostics/
   └─ last-session.json        # 最近 200 帧 hex + 状态快照（断线时刷新）
```

> 设计取舍：按用户要求采用"运行目录"而非 `%APPDATA%`——程序完全可携带（U 盘即用）；代价是 Program Files 等受保护目录无写权限，发布说明需建议放到用户目录。托盘右键菜单提供"打开日志文件夹"。

## 9. 配置、Profile 与内置校准向导

- `config.json`：`lastDeviceAddress`、`autoStart`、**`calibration`**；
- `profiles/mr5.json`（内嵌 `LogicalName=mr5.json`）：UUID、音量上限、EQ/声学调校范围、解码状态映射、信号档位阈值、退避表——**型号差异全部数据化**；
- **首次启动校准向导**（v1.2 新增，取代外部 Phase 0 标定）：音箱首次就绪后自动弹出（托盘菜单"校准向导"可重跑），
  1) 自动采集：连接、固件、音量上限、当前输入/模式/解码字节；
  2) 引导式标定：用户按提示在手机 App 切输入源（记录"字节→名称"）、把 62Hz 调到 0dB/+2dB（推得增益码表）、切三种声音模式（记录 ID）——每步均可跳过；
  3) 结果写入 `config.json → calibration`，并经 `Mr5Profile.ApplyCalibration` 覆盖 profile 运行时值。
- 未标定的降级表现：输入源显示原始字节（`0x01`）、声音模式按钮无效、EQ dB 显示按 `(code−6)×0.5dB` 假设。`tools/phase0_probe.py` 保留为高级调试工具。

## 11. CI / 发布

- **ci.yml**（push/PR）：windows-latest + setup-dotnet 10.0.x → `dotnet restore/build/test`，上传 trx；
- **release.yml**（tag `v*`）：test → `dotnet publish -r win-x64 -p:PublishSingleFile=true -p:SelfContained=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:Version=<tag>` → 单文件 `EdifierCenter.exe`（约 70–90MB）→ GitHub Release（自动 Release Notes）；
- 本机无需安装 .NET SDK：**代码 push → CI 验证 → tag 出 exe**。

## 13. 风险与开放项

- 首次 CI 可能暴露少量编译错（本地无 SDK，纯静态编写）——预期在 CI 日志中按错误逐个修复即可；
- R1 广播可用性 / R2 双 BLE 中心并发 → Phase 0 实测决定起始策略；
- 声音模式 ID、输入标签表、增益码点 → `phase0_probe.py calibrate` → 回填 `profiles/mr5.json`；
- EQ 增益码表未标定前，UI 按 `(code−6)×0.5dB` 假设换算（`Mr5Profile.EffectiveZeroGainCode/EffectiveDbPerCode` 集中一处，标定后只改 profile）。
