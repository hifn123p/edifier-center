# 04 · 代码审计报告（v0.1.3 → v0.1.4）

> 审计范围：`src/`（Core/Ble/App 全部源文件与 XAML）、`tests/`、`tools/`、`.github/workflows/`。
> 维度：安全、内存/资源泄漏、功能逻辑不对应、绑定关系错误、线程与并发、性能。
> 方法：全量通读 + 数据流跟踪（UI ↔ VM ↔ 会话 ↔ 传输 ↔ 音箱）+ 与真机实测（bleak 直连）交叉验证。

## 1. 发现清单

严重级别：P0（功能失效/崩溃）｜P1（逻辑错误/资源问题）｜P2（性能/健壮性）｜P3（一致性/文档）。除标注"观察"外均已修复并经 CI 验证。

### P0 — 功能失效

| # | 位置 | 问题 | 修复 |
|---|---|---|---|
| P0-1 | CalibrationViewModel 构造 | **`_settings` 字段声明了但从未赋值**（`_ = settings;`），`Finish()` 访问 `_settings.Calibration` 抛 NRE，被全局异常处理器吞掉 → 向导最后一步「下一步」看似无响应（真机复现的问题 1） | `_settings = settings;` |
| P0-2 | CalibrationViewModel.Finish | 只抛 `Finished` 的属性通知，但视图绑定的是计算属性 `WizardVisibility/FinishedVisibility` → **完成页永远不显示**（与 P0-1 叠加造成"最后一步按钮全部失效"） | 显式抛两个可见性属性 |
| P0-3 | TrayIconController | `HwndSourceParameters` 使用默认样式（含 WS_OVERLAPPEDWINDOW+可见）→ 启动后出现**全黑、可放大**的幽灵窗口（真机复现的问题 1 旧现象） | 改为 HWND_MESSAGE 消息专用窗口（ParentWindow=-3，样式 0，永不显示） |
| P0-4 | EdifierSession.RunReadyAsync | 就绪期子任务被 readyCts 取消时抛 OCE，被 RunAsync 的 `catch (OperationCanceledException) → return` 分支吞掉 → **Ready 期触发"手动重连"有约 50% 概率直接终止整个会话循环**，之后托盘永远不再重连 | 区分根 ct 与 readyCts 的取消：非根取消转为 `IOException("会话重启")` 走断线重连流程 |
| P0-5 | WinRtTransport.ConnectAsync | 只尝试 `ServiceUuids[0]` 一个服务 UUID——真机实测 MR5BT 分支实际为 **`48090a03`**（不在 EdifierControl 记录的 3a01/7e03 中）→ 永远"控制服务未暴露"（真机复现的连接失败根因） | 逐个尝试 profile 中全部服务 UUID；discovery 列表补 `00000a03/48090a03` |
| P0-6 | WinRtTransport.FindFirstAsync | 匹配条件只认广播中的服务 UUID → MR5BT 广播虽带 `00000a03` 但被旧列表过滤 | 三重匹配：服务 UUID / 厂商 ID `0x07E0` / 广播名 "EDIFIER BLE" |

### P1 — 逻辑错误 / 资源问题

| # | 位置 | 问题 | 修复 |
|---|---|---|---|
| P1-1 | App.OnExit | `StopAsync().GetAwaiter().GetResult()`：内部 `await` 捕获 UI 线程上下文 → **同步等待死锁**（真机复现的问题 2：退出后进程残留）；且托盘 Dispose 发生在菜单回调内部（在 WndProc 里自毁 HwndSource） | 会话层全部 `ConfigureAwait(false)`；OnExit 有界等待 3s；托盘清理统一移至 OnExit |
| P1-2 | BandVm | `GainText`（EQ 滑条旁 dB 标签）依赖 `GainDb`，但 setter 只抛 `GainDb` → **拖动时 dB 标签不跟手** | `GainDb` 变化时同时通知 `GainText` |
| P1-3 | CalibrationViewModel.NextAsync | 无基线比对：用户未切输入时点"下一步"，会把当前字节错标成新名称（如把 XLR 的字节标成"蓝牙"）；EQ 0dB 步同理会把任意码点记为零点 | 进入步骤时记录基线，状态未变化则跳过记录并计数 |
| P1-4 | MainViewModel.SendAcoustic | `_acousticMirror` 为空时用猜测值（mode=0）构造 0xC4 写入 → **可能意外切换用户当前的声音模式** | 未读到音箱实际声学状态（0xD5）前禁止发送 |
| P1-5 | WinRtTransport | `GattDeviceService` 实例无根引用（GC 回收可能关闭 GATT 会话）；RSSI watcher 每次重连新建但不清理 → **随重连次数累积** | `_service` 字段持有 + Dispose；StartRssiWatcher 先清理旧实例 |
| P1-6 | WinRtTransport.FindFirstAsync | 蓝牙开关关闭/适配器错误时 watcher 停止且不再收包，扫描**永久挂起**（日志只剩心跳） | 监听 `Stopped` 事件，错误时快速失败 → 会话退避重连 |

### P2 — 性能 / 健壮性

| # | 位置 | 问题 | 修复 |
|---|---|---|---|
| P2-1 | EdifierSession 构造 | 每条 BLE 广播（每秒可达十几次）都触发 RSSI 状态刷新 → UI 通知风暴 | 变化 <3dB 且 2s 内的读数不刷新 |
| P2-2 | MainViewModel.ApplyState | `Raise(string.Empty)` 全量重绑定，拖音量时每次乐观更新都全量求值 | 改为 23 个属性的定向刷新列表 |
| P2-3 | FileLogger | 每条日志同步写磁盘（推送高频时 I/O 尖峰）；队列无上限（磁盘满时内存无限增长）；无清理 | 内存队列 + 后台 500ms 批量落盘；上限 5000 条丢最旧；自动清理 7 天前日志 |
| P2-4 | MainViewModel.SetVolumeFromUi | 节流为"停止拖动后 150ms 才发首条"→ 长拖动期间音箱不跟手 | 首变化立即下发，拖动期间合并为每 150ms 一条，结束后补发最终值 |
| P2-5 | TrayIconFactory.Create | `Bitmap.GetHicon()` 后位图未释放 → 托盘图标状态每次变化泄漏一个 GDI 位图 | `using` 释放（GetHicon 已拷贝数据） |

### 观察项（确认为设计内行为，不修改）

- 协议**无配对/鉴权**：同族设备均可连接（Spoof 风险）——Edifier 固件固有行为，README 已声明；
- 命令队列 `DropOldest`：就绪前用户连点按钮可能丢弃最旧命令——可接受的降级；
- `SystemEvents.PowerModeChanged` 不退订：App 生命周期一致；
- `SettingsService.LastDeviceAddress` 暂未使用（M2 直连优化预留）；
- OTA/恢复出厂/关机等危险 opcode 不存在于代码路径（`CommandId` 白名单保证）。

## 2. 安全审计

| 检查项 | 结论 |
|---|---|
| 注入类（SQL/命令行/路径） | 无动态拼接执行；`Process.Start("explorer.exe", dir)` 参数为程序自身日志目录常量 |
| 配置/JSON 反序列化 | `System.Text.Json` 无多态类型绑定，输入来源为本机文件，无反序列化风险 |
| 权限边界 | 仅写运行目录（config/logs/diagnostics）+ HKCU Run（自启）；无管理员操作 |
| 网络/蓝牙攻击面 | 仅 BLE GATT 白名单命令；写操作无用户不可预期路径（声学调校需先读后写）；无 OTA/配对管理 |
| 凭据/隐私 | 不存储任何凭据；diagnostics 中的 MAC 地址本就随广播公开 |
| 供应链 | src 零第三方依赖；NuGet 仅测试框架（`*` 浮动版本，后续可锁定）；工具脚本仅本地使用 |

## 3. 内存 / 资源专项

- 事件订阅全部成对（除 App 生命周期级）；校准 VM 泄漏已修复（P3-3）；
- GDI 句柄：托盘图标旧句柄 DestroyIcon + 位图 using（P2-5）；
- BLE 资源：watcher/GattDeviceService/characteristic 随连接生命周期清理（P1-5）；
- 日志队列上限 5000（P2-3）；诊断帧环形上限 200；写队列有界 32（DropOldest）；
- 会话线程所有 await 脱离 UI 上下文，退出路径有界等待（P1-1）。
